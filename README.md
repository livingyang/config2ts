# config2ts

convert config to ts file.

# install

run command: `npm install -g config2ts`

# documentation

Full documentation is published via GitHub Pages (this repo has Pages enabled):

- English: https://livingyang.github.io/config2ts/#/docs/en
- 中文: https://livingyang.github.io/config2ts/#/docs/zh

Both the documentation pages and the per-feature demo cases are served by the
Vue site in [`website/`](website/) (built into `docs/`).

# usage

`config2ts` supports two output modes selected by `-m, --mode`:

- `single` (default): merge every table into one file (`-n`, default `csv.ts`).
- `split`: write one `.ts` file per table plus an auto-generated `index.ts`.

Every case under [`fixtures/`](fixtures/) pairs its source tables with the
single-mode merge of those tables, so you can compare input and output directly
(the demo site renders the same pairs):

- single mode example: [`fixtures/03-cross-ref/expected.ts`](fixtures/03-cross-ref/expected.ts)
- split mode: one file per table plus `index.ts` (layout shown below)

## fixtures (single source of truth)

The [`fixtures/`](fixtures/) folder holds one self-contained case directory per
feature (`01-basic-types`, `03-cross-ref`, ...). Each case contains its source
tables plus a committed golden file `expected.ts` generated from them. The same
`(input.csv, expected.ts)` pairs are used by the golden-file unit tests
([`tests/fixtures.test.ts`](tests/fixtures.test.ts)) and by the demo site, so
documentation, tests and demos can never drift from actual tool behavior.

A case may also use subdirectories: when every csv file inside a subdirectory
shares the same header and type rows, they are merged into ONE table named
after the directory (`fixtures/08-story/story/*.csv` → `StoryCsv`) — see
[fixtures/08-story](fixtures/08-story) and the "Isomorphic subdirectory merge"
section of the docs.

- Regenerate golden files: `npm run fixtures:regen` (rebuilds lib, then rewrites
  every `expected.ts`) — review the diff manually before committing; never
  blindly rewrite a failing golden file.
- Tests: every case is regenerated in-memory and compared byte-for-byte against
  its golden file, and all golden files are additionally checked with `tsc`.
- [`tests/golden/merged-formats.expected.ts`](tests/golden/merged-formats.expected.ts)
  is a composite golden: it merges tables from several cases (CSV with refs +
  INI + TOML) in a single call, which per-case goldens can't cover. It is
  regenerated by the same `fixtures:regen` run.

## demo site

[`website/`](website/) is a Vue3 + Vite site that renders every fixture case as
an input → output comparison page. It reads the same `fixtures/` pairs the tests
verify via `import.meta.glob(..., { query: "?raw" })` — no copies, no codegen —
so the demo can never drift from actual tool behavior.

- Local dev: `npm run demo:dev`
- Build: `npm run demo:build` — output goes to `docs/`, published on GitHub
  Pages at `/config2ts/` (the site owns the Pages root; `docs/` holds only the
  build output)

## single mode

Merge all config tables into a single TypeScript file.

```bash
config2ts -d fixtures/03-cross-ref -o dist -m single -n csv.ts
```

- `-n` is the merged output file name (default `csv.ts`).
- `-a` is optional; omit it to skip `assets.ts` (e.g. `-a public` indexes this
  repo's sample asset tree).
- Example output: [`fixtures/03-cross-ref/expected.ts`](fixtures/03-cross-ref/expected.ts) — all tables as `export namespace XxxCsv { ... }` in one file.

## split mode

Write one `.ts` file per config table (named after the source file, e.g.
`skill.csv` → `skill.ts`) plus an auto-generated `index.ts` that re-exports every
table and `assets.ts`. Cross-table `Ref`/`RefEnum`/`Template` references are
resolved with `import` statements injected at the top of the referencing file, so
every table is independently usable and tree-shakable.

```bash
config2ts -d fixtures/03-cross-ref -o dist -m split -a public
```

- `-n` is reused as the index file name; the single-mode default `csv.ts` is
  replaced by `index.ts` unless you pass `-n` explicitly.
- `-a` is optional; omit it to skip `assets.ts`.
- Example output: one file per table (`z-base.ts`, `a-user.ts`, `skill.ts`, …),
  plus `assets.ts` and `index.ts` (layout below).

Output layout under `dist`:

```
dist/
  z-base.ts        # export namespace ZBaseCsv { ... }
  a-user.ts        # import { ZBaseCsv } from "./z-base"; export namespace AUserCsv { ... }
  skill.ts
  ...
  assets.ts        # generated only when -a is given
  index.ts         # export * from "./z-base"; export * from "./a-user"; ...; export * from "./assets";
```

Notes:
- Tables are emitted in topological order; a table only `import`s tables it
  actually references, and missing/circular references print the same warnings as
  single mode.

# support type

| csv field  |  typescript type  |
| :--------: | :---------------: |
|   Index    |      string       |
|   String   |      string       |
|   Number   |      number       |
|  Boolean   |     boolean       |
|    Enum    |       type        |
| EnumIndex  |       type        |
| String[]   |     string[]      |
| Number[]   |     number[]      |
|  Enum[]    |      type[]       |
|    Ref     | namespace.Record  |
| RefEnum    | namespace.type    |
| RefEnum[]  | namespace.type[]  |
|  RefTable  | namespace.Record[] |
| RefTable[] | namespace.Record[][] |
|  Template  | namespace.Record  |
| Template[] | namespace.Record[] |
|   Object   |   type (Record)   |
|  Object[]  | type[] (Record[]) |

* `Number` support Infinity and NaN
* `Boolean` reads the tokens people actually type in a config table: `true/false` (case-insensitive), `1/0`, `yes/no`, `on/off`, plus `0.0`/`1.00` from spreadsheet exports; an empty cell is `false`; any other value prints a warning and becomes `false`. JS truthiness is never used, so `0` and `false` are `false`
* `Enum` support empty string type
* `Enum[]` union contains every value actually present in the data (including `""` for empty slots)
* `EnumIndex` will generate index type, and will use `Enum` type to generate interface
* `Ref` / `RefEnum` reference another csv's Record/enum by id: `Ref[table]` is one row (`table.Map["id"]`), `Ref[table][]` is an array of rows with comma-separated ids (`[table.Map["1"],table.Map["2"]]`, typed `File.Record[]`); use `Object[]` for inline private structures and `Ref[]` for shared, identity-bearing rows
* `Template[table]` inherits a whole row from another table and overrides selected fields: a cell is `<baseId>|<key>:<value>,<key>:<value>` — a pipe separates the base row id from override pairs (e.g. `101|damage:150,range:8`), emitting `{ ...table.Map["101"], damage: 150, range: 8 }` typed `File.Record`; with no overrides the cell is just the id and emits a plain `table.Map["id"]` like `Ref`. Override values may be bare scalars or bracket-wrapped composites mirroring the generated TS syntax — arrays as `[v1,v2]` (e.g. `Params:[6,2.07]`, required for array-typed fields; a bare `Params:6,2.07` gets chopped by the pair comma and prints a warning) and flat objects as `{k:v,k:v}`. `Template[table][]` separates entries with `;` (the same element separator as `Object[]`), e.g. `101|damage:150;102|heal:500` emits `[{ ...table.Map["101"], damage: 150 },{ ...table.Map["102"], heal: 500 }]`. Override key typos and value-type mismatches fail at tsc compile time; overrides are flat top-level fields (no dot-path deep merge), and the target table must have an Index/EnumIndex Map
* Reference targets are written as **table names without the extension** (`Ref[skill]` → `skill.csv`); the full file name (`Ref[skill.csv]`) still works, and an ambiguous stem (`skill.csv` + `skill.ini`) warns and needs the full name
* **Homogeneous subdirectories merge into one table named after the directory**: when every csv in a subdirectory shares the same header and type rows, `story/ch01.csv` … → `StoryCsv`, rows concatenated in file-name order. The merged table has no flat `List`; it exports `FileMap` grouped by member file plus `type File = "ch01" | ...` and `refTable(file: File)`; `RefTable[story]` references a whole member sub-table by file name (typed `StoryCsv.Record[]`, `File` union makes an unknown name a compile error). Member files that nothing references are allowed. See [`fixtures/08-story`](fixtures/08-story)
* Merge order is resolved automatically: tables are topologically sorted so every referenced table (`Ref`/`RefEnum`/`Template`/`RefTable`) is emitted before the tables referencing it — no filename tricks needed; tables without a dependency relation keep alphabetical order. Circular references (`a.csv -> b.csv -> a.csv`) and references to missing files print a warning
* `Object` parse `key:value,key:value` format, auto-infer value types (number/boolean/string), generates a dedicated `type` that merges all keys
* `Object[]` separates objects with `;` while commas still separate `key:value` pairs inside each object (same syntax as the `Object` type), e.g. `num:1,,str:a;num:2` makes `[{num:1,str:'a'},{num:2}]`, a bare `;` makes `[{},{}]`; generates a dedicated element `type` merging all keys with the field typed as `type[]`
* Array convention: primitive arrays (`String[]`/`Number[]`/`Enum[]`/`RefEnum[...] []`) separate elements with `,` and `Object[]` separates objects with `;`; raw cell values are normalized (CRLF/CR unified to LF, whitespace trimmed); an empty cell generates `[]`; otherwise n separators make n+1 slots and every slot is kept (including interior or trailing ones) so parallel arrays stay index-aligned. Empty slots use the type's own zero value — `''` for string/enum/ref-enum, `0` for number, `{}` for empty object slots; `null` is never generated
* Line breaks inside a cell (quote-wrapped in CSV) are preserved for `String` fields (emitted as `\n`) and act as the equivalent separator in structural fields — a line feed equals a comma between array elements / Object pairs / Template override pairs, and equals a semicolon between Object[] elements / Template[] entries (one entry per line works; a blank line is an empty slot by the n+1 rule). Scalar fields (Number/Boolean/Enum/single Ref) have no separator semantics, so a line break there prints a warning and must be removed
* unrecognized field types fall back to `string` and print a warning (check for typos)

## assets2ts

Scan assets directory and generate an `assets.ts` index file with nested resource tree.

- `-a, --assets <path>` set assets resource directory (optional, skip asset index if omitted)
- Output file: `assets.ts` (alongside the merged config file)
- File and directory names are used exactly as-is (e.g., `Direction.png` → `Direction`, `adjust-horizontal.png` → `'adjust-horizontal'`); keys with special characters are automatically quoted
- `type` field uses file extension (lowercase), e.g. `'png'`, `'mp3'`, `'svg'`
- Directories containing 2+ files of the same extension get a dedicated type (e.g. `PngAsset`, `Mp3Asset`) and `satisfies Record<string, XxxAsset>` annotation
- Directories with ≤1 file or mixed extensions do not get a type annotation
- Nested directories are supported (e.g. `public/sub/image/`)

### generated example

```typescript
// Auto Generated by config2ts, DO NOT EDIT

export type Mp3Asset = { path: string; type: 'mp3' };
export type PngAsset = { path: string; type: 'png' };
export type SvgAsset = { path: string; type: 'svg' };

export const ASSETS = {
    public: {
        image: {
            'adjust-horizontal': {path:'public/image/adjust-horizontal.png',type:'png'},
            Direction: {path:'public/image/Direction.png',type:'png'}
        } satisfies Record<string, PngAsset>,
        music: {
            effect1: {path:'public/music/effect1.mp3',type:'mp3'},
            effect2: {path:'public/music/effect2.mp3',type:'mp3'}
        } satisfies Record<string, Mp3Asset>,
        'single-file': {
            effect1: {path:'public/single-file/effect1.mp3',type:'mp3'}
        }
    }
};
```

### usage

```typescript
import { ASSETS } from "./assets";

const meta = ASSETS.public.image.Direction;
// meta.path → 'public/image/Direction.png'
// meta.type → 'png'

const adjustMeta = ASSETS.public.image['adjust-horizontal'];
// adjustMeta.path → 'public/image/adjust-horizontal.png'
```

## Options

```
  Options:

    -h, --help             output usage information
    -V, --version          output the version number
    -d, --dir <path>       set convert path. default: ./
    -o, --outDir <path>    set outDir path. default: same as -d
    -n, --name <name>      output file name (single mode) / index file name (split mode). default: csv.ts
    -a, --assets <path>    set assets resource directory for asset index (optional, skip asset index if omitted)
    -m, --mode <mode>      output mode: single (merge into one file) or split (one file per table + index.ts). default: single
    --auto-qualify        qualify merged-table keys as "<file>:<index>" so sibling member files that each number from 1 never collide (opt-in; see Isomorphic subdirectory merge below)
    --strict               treat un-mergeable subdirectories as errors instead of warnings (fails the build on structural skips)
    --verify-against <path>  verify generated output matches a reference snapshot (.ts, or .json wrapping the text under "source") and exit non-zero on drift, without writing output
```

## Advanced features

### Primary key and `Map`

The column typed `Index` / `EnumIndex` is the primary key: it drives the
generated `Map` (and `byKey`). Rows with an empty key are dropped. A table
needs an `Index` / `EnumIndex` column to get a `Map`.

### Optional columns in merged subdirectories

When member files of a merged subdirectory share most columns but some files omit
a few, the missing cells are padded with empty (parsed to the column's type
default) instead of rejecting the whole merge. Only a genuine type clash on a
shared column (e.g. `Number` vs `String`) is still rejected with a warning.

### Manifest merge groups (recursive)

A `config2ts.manifest.json` next to the config directory can flatten
deeply-nested csv into one virtual table, so `activities/<id>/timeline.csv`
maps to a single namespace with nested paths as sub-table keys:

```json
{ "mergeGroups": [{ "dir": "activities", "recursive": true }] }
```

When a directory is named in `mergeGroups` it is merged via the manifest path
rather than the default single-level merge, so nested files are not skipped.

### Dynamic key lookup (`byKey`)

Every index-keyed namespace (plain or merged) also exports
`byKey(key: string): Record | undefined`. This is the safe escape hatch for
consuming a merged table by a runtime string key without triggering `TS7053`;
it deliberately does **not** add a `string` index signature to `FileMap` (which
would silence the compile-time guard that catches typos like `FileMap["typo"]`).
