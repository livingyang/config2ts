## 决策：通用能力扩展方案（fixtures 单一事实来源 + 静态 demo）

背景：剧情表 CSV 设计讨论（HanmoMerge 浪漫餐厅 ch01~ch03）延伸到 config2ts 本身的通用能力扩展。

**方案要点（已归档并开工）：**

1. **不做在线 playground**。改为本地用工具预生成全部测试数据，同一份数据同时服务单元测试和 demo 展示（executable documentation / 单一事实来源），文档、测试、展示三类漂移物理上不可能发生。
2. **fixtures 按特性拆分**：`fixtures/<NN-feature>/{input.csv, expected.ts}`，一个目录只演示一个特性（primitive types / array / object / template / ref / enum-index / split...），现有 `config/` 的示例职责逐步由 fixtures 接管。
3. **golden-file 测试**：遍历 fixtures，input.csv → 转换 → diff expected.ts → 对 expected.ts 跑 tsc；更新走 `fixtures:regen` 脚本再生 + 人工 review diff，禁止自动回写。
4. **测试可私有、demo 只共享子集**：边界/告警类 fixture 可只进测试；demo 用的必须先过测试。
5. **Vue demo 站（后续 P2）**：Vue3+Vite 纯静态展示 input→output 对照（Vite `?raw` 读 fixture），无运行时转换依赖，构建产物进 `docs/app/`（base: '/config2ts/app/'），发布链路复用 HanmoTechnology 经验。源码放 `website/`，docs/ 只放产物。
6. **P0（可后置但值得做）**：lib 拆 core（纯函数，零 fs）/ node（IO+CLI），服务可测试性与未来编辑器插件/构建管线内嵌，非 playground 服务。
7. 已验证事实：config2ts `startConvert` 用 `fs.readdirSync` 非递归，章节 CSV 必须平铺在 `-d` 目录（HanmoMerge 剧情表设计结论：story-chapter.csv + story-chNN.csv 每章自包含，共享事件表只在真复用时用 Template[story-event] 引用，长文本不走 override）。

**实施顺序：** P1 fixtures 重组 + regen + golden 测试 → P2 Vue demo 站 → P0 core/node 拆分（穿插）。

## 已完成（bugfix：demo 站按钮"全部不可点击"，2026-11-04）
- 根因：`App.vue` 里 `watch(() => window.location.hash, ...)` 是死代码——`location.hash` 不是响应式数据，watch getter 无响应式依赖永不触发。hash 变了但视图永不更新，表现为全页按钮无反应。
- 定位方式：Playwright 无头点击诊断（点击后对比 hash vs DOM 状态 + 抓 console/network），复现"hash 已变、DOM 未变、零报错"。
- 修复：改监听 `hashchange` 事件 + onUnmounted 清理。无头回归验证：导航切换、侧栏切 case、elementFromPoint 命中全部通过。
- 经验：**SPA 手写 hash 路由必须用 `hashchange` 事件，不能用 watch 外部值**；Playwright 可用 `NODE_PATH=<npx-cache>/node_modules node script.cjs` 复用 npx 缓存的模块（本机 npx 缓存 playwright 1.64.1，chromium 已装）。
- 生产 bundle 已重建，测试 11/11 全绿。
