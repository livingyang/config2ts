## 发布源强制官方 registry
- 症状：`npm publish` 报 ENEEDAUTH —— 用户 ~/.npmrc 里 `registry=https://registry.npmmirror.com`，publish 会去镜像找 token，而 token 只配在 `//registry.npmjs.org/`。
- 方案：package.json 加 `publishConfig: { registry: "https://registry.npmjs.org/", access: "public" }`（npm 原生字段，对内置 `npm publish` 生效）+ `scripts.release` 显式带 `--registry` 双保险。
- 踩坑：脚本不能命名 `publish` —— 它是 npm 的 lifecycle 钩子名，`npm publish` 会触发它，脚本里再调 `npm publish` 直接自递归（三层后失败）。
- 验证：`npm publish --dry-run` 与 `npm run release -- --dry-run` 均显示 Publishing to https://registry.npmjs.org/，install 侧仍走镜像不受影响。

## 落地 HanmoMerge 优化提案（4a + 1A）
- 来源：`C:\Developer\github\HanmoMerge\docs\config2ts-optimization-proposals.md`（8 条，针对 v2.10.1 实战反馈）。先逐条核对源码事实，再落地最高价值、最低风险两项。
- **4a 数组列 JSON 字面量**：改 `splitStringArray`——单元格以 `[` 开头、`]` 结尾时尝试 `json5` 解析为数组（元素可含逗号，免 CSV 引号），失败/非 JSON 回退逗号切分，100% 向后兼容（`json5` 已是依赖）。无需新开关。
- **1A 合并键自动限定（opt-in）**：新增 CLI `--auto-qualify`，透传 `startConvert→collectConvertUnits→tryMergeSubdir→csv2ts`；合并行 key 改写为 `<file>:<index>`，并注入 `localIndex` 字段保留原 Index；自动限定下抑制 `duplicate Index key` 告警 + 限定的 key 列降级为 `string`（保证 `"file:1"` 可编译）。默认关闭，不触碰既有生成物。
- 测试：`tests/config2ts.test.ts` 新增 4 个用例（4a 解析+逗号兼容、非 JSON 回退；1A 限定后 key/localIndex/无告警/tsc 编译、关闭时仍报 dup-key 且无 localIndex）。`npm test` 单测 15/15 通过；既有 8 个 fixture golden 内容逐字节一致（仅 CRLF/LF 环境差异，与本改动无关）。
- 未做（提案其余项）：2 判别联合、3 递归+manifest、4b 矩阵类型、5 TS7053 索引签名、6 告警可操作化、7 声明式键列、8 漂移校验——其中 5 建议改用 `byKey(key): Record[]|undefined` 而非给 FileMap 加 string 索引签名以保留类型护栏。
