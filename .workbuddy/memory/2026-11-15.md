## 发布源强制官方 registry
- 症状：`npm publish` 报 ENEEDAUTH —— 用户 ~/.npmrc 里 `registry=https://registry.npmmirror.com`，publish 会去镜像找 token，而 token 只配在 `//registry.npmjs.org/`。
- 方案：package.json 加 `publishConfig: { registry: "https://registry.npmjs.org/", access: "public" }`（npm 原生字段，对内置 `npm publish` 生效）+ `scripts.release` 显式带 `--registry` 双保险。
- 踩坑：脚本不能命名 `publish` —— 它是 npm 的 lifecycle 钩子名，`npm publish` 会触发它，脚本里再调 `npm publish` 直接自递归（三层后失败）。
- 验证：`npm publish --dry-run` 与 `npm run release -- --dry-run` 均显示 Publishing to https://registry.npmjs.org/，install 侧仍走镜像不受影响。

## 落地 HanmoMerge 优化提案其余 7 项（2/3/4b/5/6/7/8）
- 按上一轮建议的优先级/改法推进，全部 opt-in、向后兼容，默认行为不变。
- **5 byKey（替代 TS7053 补丁）**：`csv2ts` 在 `Map` 块后导出 `byKey(key: string): Record | undefined`，内部 `(Map as {[k:string]:Record|undefined})[key]` 返回——**刻意不加** `string` 索引签名到 `FileMap`（保留 `"typo"` 编译期护栏）。提案原建议的索引签名方案被拒。
- **7 `# key:` 声明式主键**：`parseDirectives` 解析首部 `# key: <col>` / `# matrix: <type>` 指令（strip 后交 csvParse）；声明列不存在则告警回退类型推导。合并路径先剥离指令行以免污染合并头。
- **4b `# matrix:` 矩阵模式**：整张表作为变长二维网格导出 `Matrix: T[][]`（含 `RowCount`/`ColCount`），不走逐行 Record；T∈string|number|boolean。
- **2 合并组可选列（轻量版）**：`unifyMergedFiles` 列并集，缺列补空值（下游按类型默认解析），仅当同一列类型在多个文件冲突才拒绝并告警；复用为 manifest 组合并基础。
- **3 递归 + manifest 合并组**：`collectConvertUnits` 读 `config2ts.manifest.json` 的 `mergeGroups:[{dir,recursive}]`，递归收集 csv 并扁平为单一虚拟表；manifest 声明的目录在默认单层合并循环中跳过以免重复。`relPathWithoutExt` 用相对路径（含 `/`）作 sub-table 名。
- **6 告警可操作化 + `--strict`**：合并跳过类告警补可操作提示（声明 manifest 合并组 / 拍平单层 / 对齐列类型）；`--strict` 将结构性跳过升级为 `throw`（fail-fast）。`strict` 透传 `startConvert→collectConvertUnits→tryMergeSubdir`。
- **8 `--verify-against <ref>`**：`verifyAgainst(units, refPath)` 将生成物规范化（去 AutoGen 头 + 折叠空白）与参考快照（`.ts` 或 `.json` 的 `source`）比对，不一致打印首处差异并退出非 0；main.ts 接入，verify 模式不写文件。
- 测试：`tests/config2ts.test.ts` 新增 9 用例（byKey/编译、key 指令+回退、matrix、可选列+类型冲突、strict 抛错+提示、manifest 递归、verify 通过+漂移），单测 **24/24 通过**。
- 注意：`fixtures.test.ts` 的 9 个 golden 比对是**裸字符串**比较，而提交 golden 为 CRLF（Windows checkout）、生成物为 LF，故在本环境恒失败——属 git autocrlf 环境噪声，非回归；已用「CRLF 去除后内容逐字节一致」校验 goldens 正确（含新增 byKey）。config2ts.test.ts 的 whitespace 无关断言才是权威内容测试。
- 副作用：新增 byKey 使所有含 Index 的命名空间生成物变化，已 `npm run fixtures:regen` 更新 8 个 fixture golden + `tests/golden/merged-formats.expected.ts` + `website/src/i18n/ui.ts`（均规范化回 CRLF 以最小化 diff）。
- **serializeField 改动回滚**：最初想改成正则判断合法标识符并 JSON.stringify 引号，发现旧 json5 实现已能正确为含 `/`、空格的键加单引号，改写只会引入双引号 churn，故回滚。
